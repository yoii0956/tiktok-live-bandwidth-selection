## 5M 到底能播什么，运营机也要算带宽

先把“5M”这个词拆开。它指的是直播业务能持续稳定使用的上行带宽，不是测速软件偶尔跳到 5Mbps 的那一下。中国家庭宽带常见下行 500M、上行只有 30M，晚高峰被家人抢一波，推流码率直接腰斩。上行低于 5Mbps，直播基本就悬了。

单设备的需求大致是这样：

| 场景 | 建议带宽 | 说明 |
| --- | --- | --- |
| 手机 720P 真人出镜、聊天、带货 | 5M | 单台设备、网络稳定 |
| 手机 1080P 或多方连麦 | 8–10M | 给波动留余量 |
| 电脑 720P 推流 | 4Mbps 上传起 | LIVE Studio / OBS |
| 电脑 1080P 30fps | 10M | 静态画面偏多的场景 |
| 电脑 1080P 60fps、走播、动态画面 | 15–20M | 码率越高，预留越多 |
| 运营机（刷视频、回评论、看后台） | 每台 2–3M | 不推流，但持续占带宽 |

手机和电脑的差距来自推流方式。手机通过 TikTok App 直播，平台会按网络状况自动适配画质和码率；电脑推流的分辨率、帧率、码率都是手调的，参数拉高，上传需求跟着涨。

多设备场景里最容易漏算的是运营机。一台手机直播配一台手机回评论、看数据，是多数小团队的标准配置，这条运营机同样吃带宽。按保守口径算：5M 只承担 1 台直播机，运营机单独加 2–3M。

- 1 台直播 + 1 台运营 ≈ 8M，实际买 10M
- 2 台直播 + 2 台运营 ≈ 16M，实际买 20M
- 4 台直播 + 3 台运营 ≈ 29M，实际买 30M

有服务商把 5M 标成“1 台直播 + 1 台运营”，也有服务商按每 5M 一台直播设备报价。差别就在运营机算不算进去。按设备数相乘再加 30% 冗余，这个算法放在哪家都不会出大错。

**查 IP 归属地和 DNS 落点。** 拿到测试 IP 后用 ipleak.net 看两栏：IP 注册地是否落在目标国家，DNS 解析是否也在当地。IP 对了但 DNS 走了别处，平台一样能判出来。WePC 这类原生 IP 的价值就在这里，机房 IP 和住宅 IP 在 ASN 归属上一查便知。

**看 15 分钟推流码率曲线，不看 Ping。** Ping 值低只说明往返快，说明不了持续上行稳不稳。开着直播推 15 分钟，看码率曲线是平的还是锯齿状的，锯齿状就意味着平台会把你的直播间踢出高清推流池。

## 买了专线还是标黄，先排查 IP

标黄、限流、封号是三件事。标黄表现为画面偏黄、马赛克、码率掉，推荐流减少但不归零，账号还能开播，轻度情况 3–7 天能改善；伴随推荐流归零的中度情况，通常要 7–14 天。平台判定降权的触发点主要有三个：推流码率波动大、网络抖动超标、IP 环境异常。

换了三四条线路还是标黄，问题多半出在 IP 本身，不是带宽不够。机房 IP、被大量共享过的住宅 IP，风控一眼能识别。另一个常见错误是一条线路挂多个直播号，多号共用同一出口 IP 容易触发关联限流。一条专线对应一个直播号，这条规则比带宽大小更影响账号能活多久。

恢复顺序按这个走：停播 24–48 小时，期间正常刷视频；发 1–2 条非带货短视频洗权重；恢复期前 10 分钟只互动不卖货；还标黄就换干净的网络环境。
